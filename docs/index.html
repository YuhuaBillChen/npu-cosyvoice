npu-cosyvoice

Speech-to-text and text-to-speech on the NPU most Ryzen AI laptops never use. Point any chat client that speaks the OpenAI audio API at it, and the LLM gets a voice (any voice, from a few seconds of recording), while the CPU cores stay free for the LLM itself.

让锐龙 AI 笔记本里那块平时闲着的 NPU 负责"听"和"说"。任何支持 OpenAI 语音接口的聊天软件接上它，大模型就能语音对话，音色还能换成任何人（几秒录音即可），CPU 核心则留给大模型本身。

What it does做什么

STT

Listening

Your speech → text. whisper-xdna runs the Whisper large-v3-turbo encoder on the NPU. A 5 s sentence comes back as text in about 3 s.

听

你说的话 → 文字。whisper-xdna 在 NPU 上运行 Whisper large-v3-turbo 编码器，一句 5 秒的话约 3 秒出文字。

TTS

Speaking

The reply → speech. CosyVoice3's flow decoder, the part that takes most of the time, runs int8 on the NPU; 6 s of speech is synthesized in about 4 s.

说

AI 的回复 → 语音。CosyVoice3 最耗时的部分（flow 解码器）以 int8 跑在 NPU 上，6 秒语音约 4 秒合成完。

NPU

Sharing one chip

STT gets 5 of the NPU's 6 hardware contexts, TTS gets one. When someone speaks, recognition has priority and synthesis pauses between layers, so STT is not slowed by a talking TTS.

共用一块芯片

NPU 共 6 个硬件上下文，识别用 5 个，合成用 1 个。有人说话时识别优先，合成在层与层之间暂停让路，所以识别不会被正在说话的合成拖慢。

Your own voice用你自己的声音

Any voice works: give it a few seconds of clean recording and its transcript, and it speaks in that voice, in English, Chinese and several more languages. Below, a 7.5 s public-domain LJ Speech clip became a new voice.

Install安装

A Ryzen AI 7040/8040 machine with Linux 6.14+ (for the amdxdna driver) and Docker:

需要锐龙 AI 7040/8040 机器、Linux 6.14 以上（自带 amdxdna 驱动）和 Docker：

$ git clone https://github.com/YuhuaBillChen/npu-cosyvoice.git && cd npu-cosyvoice
$ export RENDER_GID=$(getent group render | cut -d: -f3)
$ docker compose -f voice/compose.yml run --rm setup        # once, ~15 min
$ docker compose -f voice/compose.yml --profile stt up -d
$ curl localhost:8000/v1/audio/speech -H 'Content-Type: application/json' \
      -d '{"input": "Hello from the NPU.", "response_format": "mp3"}' -o hello.mp3

Then in Open WebUI: Admin Settings → Audio, both engines "OpenAI", URL http://<host>:8000/v1, TTS model cosyvoice3, STT model whisper. Any other client that supports the OpenAI audio API works the same way.

然后在 Open WebUI：管理员设置 → 音频，语音识别和语音合成引擎都选 "OpenAI"，地址填 http://<主机>:8000/v1，TTS 模型 cosyvoice3，STT 模型 whisper。其他支持 OpenAI 语音接口的客户端同理。

How it works, in one paragraph原理一段话

CosyVoice3 spends most of its time in a 22-block transformer (the flow DiT) that it runs 10 times per sentence. npu-cosyvoice moves every matrix multiply of that transformer to the NPU as int8 (W8A8 with SmoothQuant on the sensitive layer) through one compiled MLIR-AIE kernel, keeps the small operations in AVX-512 C++ on a few host threads, and runs the text model through llama.cpp. The number of flow steps adapts per sentence to the playback deadline. A tiny shared file lets the STT service pause the TTS between layers.

CosyVoice3 大部分时间花在一个 22 层的 transformer（flow DiT）上，每句话要跑 10 遍。npu-cosyvoice 把这个 transformer 的所有矩阵乘法以 int8 放到 NPU 上（W8A8，对敏感层使用 SmoothQuant），只用一个编译好的 MLIR-AIE 内核；其余小运算用 AVX-512 C++ 在少数几个 CPU 线程上完成；文本模型走 llama.cpp。flow 的步数按播放截止时间逐句自适应。一个很小的共享文件让识别服务能让合成在层间暂停。

Hardware硬件

Tested on XDNA1 (Ryzen AI 7040 "Phoenix" and 8040 "Hawk Point"). XDNA2 (Ryzen AI 300, Strix Halo, Krackan) builds with one flag but is untested; if you own one, running tests/check_gemm.py and reporting the result in an issue would make it a supported platform.

已在 XDNA1（锐龙 AI 7040 "Phoenix"、8040 "Hawk Point"）上测试。XDNA2（锐龙 AI 300、Strix Halo、Krackan）加一个参数即可编译，但未经测试；如果你有这类机器，运行 tests/check_gemm.py 并在 issue 里报告结果，就能让它成为正式支持的平台。
